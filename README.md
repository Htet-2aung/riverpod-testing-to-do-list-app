# Flutter Productivity Suite (iOS Style)

A comprehensive, all-in-one productivity suite built with Flutter and Riverpod, powered by a Firebase backend and featuring real-time Google Calendar synchronization. This application is designed with a UI-first approach, leveraging Flutter's Cupertino widget set to achieve a premium, native iOS look and feel, complete with blur effects and native navigation patterns.

This project serves as an in-depth demonstration of complex state management, third-party API integration, and authentication in a real-world Flutter application.

## Project Status

**Currently in development.** Core functionality, including Firebase Authentication and Google Calendar API fetching, is complete.

## Key Features

The application is divided into five main tabs:

### 1. Authentication
* **Email & Password:** Full Sign In, Sign Up, and "Forgot Password" flow.
* **Google Sign-In:** Secure authentication via Firebase Auth and the Google provider, requesting Google Calendar permissions.
* **State Management:** The app reacts to auth changes in real-time, automatically routing the user.

### 2. Tasks (To-Do List)
* Full CRUD (Create, Read, Edit, Delete) functionality for tasks.
* **Priorities:** Assign High, Medium, Low, or No priority to tasks, which are reflected visually.
* **Filters:** Filter the task list by "All," "Active," or "Completed" using a `CupertinoSegmentedControl`.
* **Clear Completed:** A dedicated button to permanently delete all completed tasks.
* Tap any task to edit it in a modal view.

### 3. Calendar
* **Real Google Calendar Sync:** Reads events directly from the user's "primary" Google Calendar (if signed in) using the Google Calendar API.
* **Manual Events:** Allows users to add manual events that are stored locally via Riverpod.
* **Combined View:** Displays a unified list of both Google Calendar events and manual events.
* **Swipe to Delete:** Delete manual events with a swipe gesture.
* **Date Picker:** A modal `CupertinoDatePicker` allows the user to jump to any day.
* **Sync Status Bar:** Visually indicates whether the user is connected and synced with Google Calendar.

### 4. Notes (Notepad)
* A simple, iOS-style notepad for quick notes.
* Full CRUD (Create, Edit, Delete) functionality.
* **Auto-Titling:** If no title is provided, the first line of the note is automatically used as the title.
* **Auto-Save/Delete:** Notes are saved on "Done." If both title and content are empty, the note is automatically discarded/deleted.
* **Swipe to Delete:** Delete notes directly from the main list.

### 5. Pomodoro Timer
* A productivity timer with Work, Short Break, and Long Break phases.
* **Customizable Settings:** A dedicated settings screen allows the user to adjust the duration for each phase using `CupertinoSlider`.
* **Round Counter:** Tracks completed work cycles to initiate a long break.
* Controls for Start, Pause, Skip, and Reset.

## Technical Architecture & Tech Stack

This project demonstrates clean, decoupled state management by separating the UI from the business logic.

* **Framework:** Flutter (using `CupertinoApp` and Cupertino widgets).
* **State Management:** **Riverpod**
    * `Provider`: Used for injecting services (`AuthService`).
    * `StateProvider`: Used for simple UI states (filters, dark mode, loading status).
    * `StateNotifierProvider`: Used for complex business logic (Tasks list, Notes, Pomodoro Settings).
    * `StreamProvider`: Used for the real-time Firebase authentication state (`authStateProvider`).
    * `FutureProvider`: Used for asynchronous API calls (`calendarApiProvider`, `calendarEventsProvider`).
    * `ref.invalidate()`: Used to reset all app-state providers on user logout.

* **Backend & APIs:**
    * **Firebase Authentication:** Handles Email/Password and Google Sign-In.
    * **Google Calendar API:** Uses `googleapis` and `googleapis_auth` to create an authenticated HTTP client and make secure API calls to read calendar events.
    * **Firebase Core:** Configured via `firebase_options.dart` (generated by `flutterfire_cli`).

* **UI (Cupertino):**
    * `CupertinoTabScaffold` for main navigation.
    * `CupertinoNavigationBar` with background blur effect (`backgroundColor` with opacity).
    * `CupertinoListSection.insetGrouped` for the native iOS-style Settings screen.
    * `AsyncValue.when` for cleanly handling Loading, Data, and Error states from `FutureProvider`s (especially on the Calendar screen).

## Getting Started

This project requires significant cloud service configuration (Firebase and Google Cloud) to run.

### 1. Clone and Prep

1.  Clone this repository.
2.  Ensure you have all dependencies by running:
    ```bash
    flutter pub get
    ```

### 2. Firebase Setup (Required)

1.  Create a new project in the [Firebase Console](https://console.firebase.google.com/).
2.  Install the Firebase CLI and FlutterFire CLI if you haven't already:
    ```bash
    dart pub global activate flutterfire_cli
    firebase login
    ```
3.  In your local project root, configure your app:
    ```bash
    flutterfire configure
    ```
    * Select your Firebase project from the list.
    * Select the `web`, `android`, and `ios` platforms. This will generate your `lib/firebase_options.dart` file.
4.  In the Firebase Console, go to **Authentication** -> **Sign-in method**.
    * Enable the **Email/Password** provider.
    * Enable the **Google** provider. (You will need to add SHA-1 fingerprints for Android).

### 3. Google Cloud Console Setup (Required)

Google Sign-In *does not* grant Calendar access by default. You must enable the APIs manually.

1.  Go to the [Google Cloud Console](https://console.cloud.google.com/).
2.  In the top dropdown, select the project you just created in Firebase (it will have the same name).
3.  **Enable APIs:**
    * Go to **APIs & Services** -> **Enabled APIs & services**.
    * Click **+ ENABLE APIS AND SERVICES**.
    * Search for and enable the **Google Calendar API**.
    * Search for and enable the **People API** (this is required for Google Sign-In to fetch user profiles).
4.  **Configure OAuth Consent Screen:**
    * Go to **APIs & Services** -> **OAuth consent screen**.
    * Set **User Type** to **External**.
    * Fill out the required app info (app name, support email).
    * On the **"Scopes"** page, click **"Add or Remove Scopes"** and add the scope: `.../auth/calendar.readonly`.
    * On the **"Test users"** page, **add your own Google email address**. This is a critical step; otherwise, you will get a `403: access_denied` error.
5.  **Configure Credentials:**
    * Go to **APIs & Services** -> **Credentials**.
    * Find the **OAuth 2.0 Client ID** for your web application (created by Firebase). Click the pencil icon to edit it.
    * Under **"Authorized redirect URIs"** (+ ADD URI), you **must** add the URL of your development environment (like Codespaces).
        * `http://localhost:[PORT]` (for local development)
        * `https://[YOUR-CODESPACE-URL].app.github.dev` (Example for Codespaces)
        * `https://[YOUR-CODESPACE-URL].app.github.dev/__/auth/handler` (The Firebase handler)

### 4. Run the App

After completing the setup, you can run the app. For a Codespace environment:

flutter run -d web-server
